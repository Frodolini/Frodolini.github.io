Asymmetrisk kryptering

To nøklar som høyrer saman: ein offentleg som alle kan få, og ein privat som berre eigaren har. Det som er låst med den eine, kan berre låsast opp med den andre.

Idéen: ei postkasse

Bob har ei postkasse med ei sprekk. Alle kan putte brev inn (den offentlege nøkkelen), men berre Bob har nøkkelen som opnar postkassa (den private nøkkelen). Bob kan fritt dele den offentlege nøkkelen med heile verda. Då slepp Alice og Bob å møtast for å dele ein hemmeleg nøkkel, som var problemet med symmetrisk kryptering.

Utfordring: kan du finne p og q når n = 3233?
        
3233 = 61 × 53. Med små tal klarer du det med kalkulator. Med eit n på over 600 siffer finst det ingen kjend metode som klarer det innan rimeleg tid. Det er heile tryggleiken i RSA: det er lett å gange saman to primtal, men svært vanskeleg å finne dei att.

Til ettertanke

    
Kva skjer om Bob mistar den private nøkkelen?
        
Då kan ingen dekryptere meldingar som er sende til han, heller ikkje Bob sjølv. Difor er det viktig med trygge sikkerheitskopiar av private nøklar.

    
Kva skjer om Eve stel den private nøkkelen til Bob?
        
Då kan ho lese alt som blir sendt til Bob, og ho kan signere meldingar som om ho var Bob. Nøkkelen må då trekkjast tilbake og bytast ut.

    
Korleis veit Alice at den offentlege nøkkelen verkeleg er Bob sin?
        
Det er ikkje sjølvsagt! Eve kunne gitt Alice sin eigen nøkkel og late som ho var Bob. Difor finst sertifikat: ein tiltrudd tredjepart signerer at «denne nøkkelen høyrer til Bob». Det er hengelåsen i adressefeltet til nettlesaren.

    
Kvifor kan ein ikkje kryptere ein heil film med RSA?
        
RSA kan berre kryptere små datamengder om gongen (her maks 190 byte) og er svært tregt. Ein krypterer heller ein tilfeldig AES-nøkkel med RSA, og filmen med AES.
